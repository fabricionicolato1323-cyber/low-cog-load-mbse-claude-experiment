# ADR-0002: Identity and ChangeSet model - what Slice 0 constrains

Status: **Proposed (partial)**. Slice 0 tested the *storage and validation mechanics* of the model in `TECHNOLOGY_STACK_DECISION.md` §3.1-3.2; it did not design the final op set, candidate lifecycle, alias/merge or authority metadata. Those remain Slice 1-3 decisions.
Date: 2026-09-20
Amends: `TECHNOLOGY_STACK_DECISION.md` §3.1, §3.2 (adds rules below).

## Context
Identity, provenance, ChangeSet and contract shape are the decisions rated "expensive to reverse". Before Slice 1 hardens them, Slice 0 built throwaway prototypes (S1 in-memory graph, S2 SQLite store) and property/crash tests over them, to learn which parts of the design survive contact with realistic data. Evidence: `docs/slice0/EVIDENCE.md` §S1, §S2, §Contracts; raw data in `docs/slice0/data/`.

## Decision (mechanics that held up, plus rules the spikes forced)

1. **Opaque string ids (UUIDv7 form), generated by the actor.** Measured at Tier 2 (10^5 elements / 10^6 relations, 36-char string ids, objects not interned): 650 MB heap after load against a 2,240 MB default Node heap limit (29%). No interning or numeric ids needed for Tier 2. Revisit only if a larger tier becomes a target.
2. **Relations stored once; forward and inverse adjacency built at load.** Forward/inverse agreement is an invariant (tested against an independent oracle).
3. **The change log is the source of truth; materialised rows are versioned (`rev_from`, `rev_to`).** *Rebuilding all versioned rows from the log reproduces the live state bit-for-bit* (SHA-256 over every row including history) at Tier 1 and Tier 2, after a normal run and after SIGKILL crashes. As-of neighbourhood lookup is index-only: p95 0.3 ms at Tier 2.
4. **Rule forced by a property-test failure: updates to the same element inside one ChangeSet coalesce into the single version row for that revision.** Without it, two updates in one ChangeSet violate the `(id, rev_from)` key. Replay must apply the same rule, which is why it belongs in the ChangeSet semantics and not in the store adapter alone.
5. **Commit protocol:** `BEGIN IMMEDIATE` -> idempotency-key lookup (a hit returns the original revision and writes nothing) -> `baseRevision == head` check (stale => typed error; semantic rebase is Slice 5) -> log row + materialised rows -> `COMMIT`. Any failure rolls back everything including the log row; a failed attempt does *not* consume its idempotency key. `synchronous=FULL` is retained (never weakened to meet latency).
6. **Wire contracts:** JSON Schema 2020-12 generated from zod, `strictObject` everywhere (zod strips unknown keys by default, JSON Schema `additionalProperties:false` does not; strict makes them agree), discriminated unions on a literal `op`/`kind` field, **no `.refine()` in wire schemas** (a refinement is silently absent from the emitted schema; semantic validation lives in the kernel validator). Tested by a 3,000-mutation differential fuzz between zod and Ajv.
7. **Traversal results need a budget, not only paging.** A 3-hop query from a hub returned 36,000 reached elements even with a 100-row page: the *count* is computed by full traversal. The Query IR (ADR in Slice 3) must carry an explicit traversal budget and report truncation; do not rely on paging to bound work.

## Consequences
- Slice 1 can start from these mechanics; it must re-implement (not import) the prototypes under kernel purity rules.
- The store adapter tests must include the rebuild-equality property and the crash tests from S2 as a standing suite (they are the only guard for rule 4).
- Rebuild-from-log at Tier 2 took 127 s (budget 120 s, see ADR-0001): acceptable for recovery, but a faster replay path is a follow-up before Slice 13.

## Not decided here
Final op vocabulary; candidate tables and lifecycle; alias/merge ops; authority metadata; provenance reference shapes; semantic rebase; undo. Wire schemas in `packages/contracts/src/probe.ts` are probes, not the contract.

## Revisit when
A Slice 1 prototype cannot express a required op under rule 4; or a Tier 3 target (> 10^6 relations) is set; or the differential fuzz finds a zod/JSON Schema disagreement.
